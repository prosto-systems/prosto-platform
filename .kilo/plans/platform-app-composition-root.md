# Composition Root in @prosto/platform-app

## Decisions and Boundaries

- The publishable `packages/platform-app` is the application composition root, not part of the core/SDK and not a discoverable module. It takes over assembly and lifecycle management, `LocalRestartRequester`, `getTrustedIngressAddresses`, and `getTlsOptions` from `examples/admin-production/src/index.ts`; the latter three implementations remain **internal**. The dependency direction is based on `docs/adr/0001-required-runtime-adapters.md` and `packages/platform-core/src/runtime/interfaces/runtime-builder-options.interface.ts`.
- When `adapters` is absent, the package builds a default preset of `FastifyHttpAdapter` + `TypeOrmPersistenceAdapter` + `PlatformAdminTypeOrmAdapter`; when present, it accepts exactly a complete set of SDK adapters (`IRequiredRuntimeAdapters`). Despite its generic name, the package does not claim that the preset is universal. With custom adapters, ingress/TLS environment variables are not read: the supplied adapter itself is responsible for HTTP security.
- One active host per Node.js process: a concurrent second start is rejected before runtime construction, and a new start is allowed once stop completes. The guard mechanism must account for concurrent calls and reloading the package within the same process. The external supervisor, PostgreSQL, the `pg` driver, and module artifacts belong to the deployment/application.

## Implementation Steps

1. Create `packages/platform-app` following the existing publishable-package template: `package.json` with root `exports`, `src/index.ts` as the API barrel, grouped `src/interfaces/` and internal implementations, `tests/`, `vite.config.ts`, `vitest.config.ts`, and `tsconfig*.json`. Dependencies: SDK, core, three adapters, `reflect-metadata`, and Zod; Vite 8/`vite-plugin-dts`/Vitest tooling in devDependencies. Externalize package dependencies; import `reflect-metadata` before TypeORM. Do not make `pg` mandatory in custom mode: it remains the consumer application's dependency.
2. Define JSDoc-documented `@alpha` types and `startPlatformApp(options): Promise<IPlatformAppHandle>`. An absolute `configDir` is required; expose the relevant `RuntimeBuilder` parameters (`environment`, `commandLineArgs`, `correlationId`, `platformPersistenceDescriptor`, synchronous `configureServices`) through typed fields. TypeScript option variants must prevent mixing preset-only settings with custom `adapters`; runtime validation checks paths and the complete adapter set. For the preset: default `host`/`port` of `127.0.0.1:3001`, optional absolute `staticSiteRootPath`, and a pair of absolute localhost PEM paths. The handle contains `runtime` for reporting/invalidation, `url?: URL` (Fastify preset only), and idempotent `stop(): Promise<void>`; the host must be stopped through `handle.stop()`, not the exposed `handle.runtime.stop()`.
3. Move parsing of `PROSTO_TRUSTED_INGRESS_ADDRESSES`, `PROSTO_TLS_CERTIFICATE_PATH`, `PROSTO_TLS_PRIVATE_KEY_PATH`, and `PROSTO_LOCALHOST` into the preset. Parse JSON as `unknown`, then validate it as a non-empty string array with Zod; the Fastify adapter additionally validates IP/CIDR values and limits. Errors must not include raw environment values or Zod issues containing `received` input. Explicit TLS PEM paths are accepted only as a pair and take precedence; when `PROSTO_LOCALHOST=true` and explicit TLS environment variables are absent, require both supplied localhost PEM path options; otherwise TLS is absent. Do not resolve the certificate path relative to the installed package; the static shell is optional.
4. Build `RuntimeBuilder` with the three adapters; in `configureServices`, first register the default `HOST_RESTART_CAPABILITY_SERVICE_TOKEN`, then invoke the user callback. The user may replace this token through `services.override` or remove it; after replacement, responsibility for idempotence/exit 75 and production admin adapter requirements transfers to them. The default requester synchronously records restart intent, waits 100 ms to flush the accepted `202`, then uses the **shared** shutdown path; repeated calls return one Promise. An accepted restart takes precedence over a `SIGTERM` received during the delay: exit code 75 applies even if shutdown fails, and `runtime.stop()` is called only once.
5. Reserve the one-host-per-process right before asynchronous startup; release it on startup failure and after shutdown completes. After `runtime.start()`, check `runtime.started`/`reports.startup.status`: in core, a start with `RuntimeStartupStatus.Failed` sometimes **returns without throwing** after already stopping the runtime (`packages/platform-core/src/runtime/platform-runtime.ts:175-189`); treat this as an error, do not return a handle, and do not install signal handlers. A degraded started runtime is allowed with a warning. After successful startup, register `SIGINT`/`SIGTERM`; signal handlers, `handle.stop()`, and restart share a single shutdown Promise and remove handlers in `finally`. A normal error-free shutdown results in exit 0; a rejected `runtime.stop()` **or** `reports.shutdown.issues.length > 0` results in exit 1 and a rejected `handle.stop()` with a safe error; an accepted restart takes precedence with 75. Log only fixed messages and safe report fields (for example, status, correlationId, and issue count), not raw exception/config/report objects. Rethrow the original startup exception to programmatic callers; the example catch logs a safe message and sets exit 1.
6. Simplify `examples/admin-production/src/index.ts`: pass absolute paths for `config/`, the built `packages/platform-admin-shell/dist`, and local `certificates/localhost-*.pem`, call `startPlatformApp`, and handle errors with a safe catch. Preserve the existing `start`/`start:localhost`, environment variables, port, and discovery/probing paths. Add the workspace dependency, update the lockfile through npm and the example's `build:dependencies`. Document the API, preset/custom modes, and supervisor exit 75 in the new package README, and update `examples/admin-production/README.md` and `AGENTS.md` for new scripts/boundaries.

## Verification and Constraints

- Vitest tests with SDK-only fake adapters for lifecycle and no real database/network: preset/custom options, no environment reads in custom mode, valid/empty/malformed ingress JSON and invalid IP/CIDR, TLS pair/precedence/local PEM, service construction and permitted override, successful/degraded/silent-failed/throwing startup, rejection of a second host, and release of the reservation after failed startup/stop. Isolate environment variables/exitCode/process listeners/fake timers; invoke captured signal handlers rather than sending actual signals to the test process. Verify the 100 ms flush, restart+SIGTERM race, one stop, listener cleanup, rejected stop on shutdown issues, exits 0/1/75, and absence of secrets in logs.
- Verify after updating dependencies and building upstream: `npm run build --workspace=@prosto/platform-app`, `npm run typecheck --workspace=@prosto/platform-app`, `npm run test --workspace=@prosto/platform-app`, `npm run typecheck --workspace=@examples/admin-production`, `npm run build --workspace=@examples/admin-production`; then run root `npm run lint`, `npm run format`, `npm run test`, and `npm run typecheck`. Direct workspace scripts require dependencies to be built beforehand; root Turborepo tasks build them according to the graph. Smoke-test `start:localhost` only with provided database/production-secret settings; do not create them for the test.
- The package does not change SDK/core and is not imported by either. Verify the npm export/d.ts/`reflect-metadata` side effect, no imports of another workspace's internal files, and preservation of absolute host paths. A custom HTTP adapter has no SDK URL, so `handle.url` is absent. Direct `runtime.stop()` is unsupported for process-handler cleanup; environments with multiple active hosts in one process are out of scope.
